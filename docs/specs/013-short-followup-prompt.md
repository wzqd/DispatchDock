# 013 接着同一个对话派发时，只发简短提醒和任务

状态：已验收（2026-11-25）

## 背景

- 派发指令在 `skills/codex-dispatch/lib/options.mjs` 的 `taskDetails` 里拼好，开头固定是一段说明：角色（有 `--role` 时）、先读 AGENTS.md、执行中不要弹出确认提示（最长的一段）、读角色文档（有 `--role` 时），然后才是任务位置或任务文字，最后是补充说明。
- 011 起默认接着同一仓库、同一角色上次用的对话。同一个对话里每派一次，这段说明就原样重发一次。用户在桌面版里看到每条消息开头都是一大串重复内容，要找任务在哪反而费劲（用户 2026-11-25 提出）。
- 这段说明大约两三百 token，比起每轮几万 token 的输入，省下的不多；主要是让桌面版里的对话好读。
- 现在指令在确定对话之前就拼好了：对话是在适配器 `executeCodex`（`adapters/codex-threads.mjs`）里才确定的。托管时请求里只带参数（`args.task`、`args.extra`、`args.role`），执行者重新拼指令。

## 目标

接着一个**已经收到过同样完整说明**的对话派发时，只发一行简短提醒，加上任务和补充说明。其余情况照旧发完整版。

## 做法

### 1. 完整版和简短版

把现在的指令分成两部分：

- **说明部分**：任务那一行之前的各行（角色、AGENTS.md、不弹确认、角色文档；没有的行不出现），用 `\n` 连接。
- **任务部分**：任务那一行，加上补充说明。

完整版和现在**逐字一致**（说明部分 + `然后完成任务说明 …` 或 `任务：\n…` + 补充说明）。

简短版 = 一行提醒 + 任务部分，任务那一行换成"新任务"的写法。文案见第 4 节。

### 2. 什么时候发简短版

满足以下全部条件时发简短版，否则发完整版：

1. 接着已有的对话（`mode` 是 `resume` 或 `specified`）。新开的对话、上次的对话没了改为新开的，一律发完整版。
2. 这个对话**最近 50 轮**里，有一条用户消息以**本次的说明部分**加一个换行开头（逐字比较）。
   - 判断依据是对话历史本身，不用 `runs.jsonl`。原因：上一次派发可能排进队列后一直没执行（例如 60 秒没开始，之后队列被清掉）；`--thread` 指定的对话可能是用户自己在桌面版里开的，从来没收到过说明。这两种情况都只能从历史里看出来。
   - 角色不同、有没有 AGENTS.md 不同、以后说明文字改了，说明部分就不一样，自然会发完整版，不用单独判断。
   - 只看最近 50 轮：超过 50 轮之前发的说明，很可能已经被 Codex 压缩掉了，重发一次完整版正好。
   - 准备那一轮（`这是 DispatchDock 的派发对话…`）不是完整说明，不算。
3. 读历史成功。读不到（报错、超时）就发完整版，任务照常执行，进度里不写额外的行。【实现时核实】读最近 50 轮用户消息最轻的办法（`thread/turns/list` 的哪种 `itemsView`，或者别的接口），给出一次长对话上的耗时和数据量作证据。

交给桌面版和后台执行两种方式都按这个规则。托管时由执行者判断。

### 3. 实现要点

- 指令要在确定对话之后再定稿。`taskDetails` 改为同时给出完整版、说明部分和简短版（或给出拼装所需的部分），适配器确定对话后选用一个。
- 选定后，`codex queue --message`、后台的 `turn/start`、按全文匹配本次那一轮（`queuedTurn` 里和 `prompt` 逐字比较的地方）都必须用**实际发出的那一版**。
- 用了简短版时，进度里写一行 `指令：` 开头的说明（文案见第 4 节），紧跟在 `对话：`、`执行：` 之后。非托管时同样打印到标准输出（和 `对话：` 行一样走 `announce`）。发完整版不写这一行。
- `CODEX_DRY_RUN=1` 不连接 Codex，判断不了用哪一版：照旧打印完整版，后面再打印简短版，中间用第 4 节的分隔行隔开。

### 4. 文案（定稿）

简短版的提醒行（三种情况三选一）：

| 情况 | 提醒行 |
|---|---|
| 有角色 | `继续以「<角色名>」的身份工作，规则同前（AGENTS.md、角色文档 <角色文档路径>、不弹出确认提示）；这些文件在上次任务之后有新提交的，先重读。` |
| 没有角色，有 AGENTS.md | `规则同前（AGENTS.md、不弹出确认提示）；AGENTS.md 在上次任务之后有新提交的，先重读。` |
| 没有角色，也没有 AGENTS.md | `规则同前（不弹出确认提示）。` |

有角色但仓库没有 AGENTS.md 时，有角色那一行去掉 `AGENTS.md、`。

简短版的任务行：

| 情况 | 任务行 |
|---|---|
| 任务说明文件 | `新任务：完成任务说明 <路径> 中的全部内容，按要求验证、提交，最后给出汇报。` |
| 任务文字 | `新任务：`，换行，接任务文字 |

补充说明照旧接在最后。

示例（有角色、任务说明文件）：

```
继续以「工程负责人」的身份工作，规则同前（AGENTS.md、角色文档 docs/roles/engineering.md、不弹出确认提示）；这些文件在上次任务之后有新提交的，先重读。
新任务：完成任务说明 docs/specs/014-xxx.md 中的全部内容，按要求验证、提交，最后给出汇报。
```

进度和 dry-run：

| 情况 | 文案 |
|---|---|
| 用了简短版 | `指令：这个对话里已有同样的完整说明，本次只发简短提醒和任务` |
| dry-run 两版之间的分隔行 | `----（接着已有同样完整说明的对话时，改发：）` |

### 5. 协议（已写进 `docs/protocol.md` 3.2）

- `progress.log` 新前缀 `指令：`（013），只在用了简短版时出现，位置在 `对话：`、`执行：` 之后。
- 其余不变：`runs.jsonl`、托管请求、`events.jsonl` 都不加字段。

## 不做什么

- 不改完整版的任何文字。
- 不加开关或配置项，不加命令行参数强制发完整版（需要时用 `--new-thread`）。
- 不改对话复用规则、执行方式、监控软件界面和文案。
- 不改 SKILL.md、`docs/protocol.md`：由设计负责人改（协议的 `指令：` 前缀已写好），工程只在汇报里写需要同步的地方。

## 允许改动的文件

## 验收

- `npm run verify` 通过。
- 假 app-server 测试覆盖：
  - 新开对话、上次的对话没了改为新开：完整版。
  - 默认复用，历史最近 50 轮里有同样的说明部分：简短版，进度有 `指令：` 行。
  - 历史里只有准备那一轮；`--thread` 指定的对话从没收到过说明：完整版，没有 `指令：` 行。
  - 历史里是另一个角色的说明、或没有角色时的说明：完整版。
  - 同样的说明只出现在 50 轮之前：完整版。
  - 读历史报错：完整版，任务照常执行。
  - 以上在交给桌面版和后台执行两种方式下都成立；托管请求同样成立。
  - 任务说明文件、任务文字两种任务；有补充说明时两版都带上。
  - 用简短版时，排进队列的消息、后台 `turn/start` 的输入、按全文匹配本次那一轮用的都是简短版。
  - 完整版和改动前逐字一致（用改动前的输出做对照样例）。
  - dry-run 输出两版和分隔行，不连接 Codex、不写文件。
- 【实现时核实】用真实 Codex 和桌面版，在临时 git 仓库里（隔离 `CODEX_DISPATCH_HOME`，只读任务即可）：
  1. 新开对话派第一次：完整版。
  2. 同一对话再派一次：桌面版里这条消息是简短版，Codex 照常读任务、完成、给出汇报。

  - 测试对话不要归档或删除，汇报里列出 ID 和每次实际发出的消息全文，验收时设计负责人在桌面版里看。
