# 011 派发交给 Codex 桌面版实时执行，默认复用对话

状态：草案（2026-11-24，第二版：按用户意见改为交给桌面版实时执行）

## 背景（已查明，2026-11-24 本机实测，Codex CLI 0.172.0）

- 桌面版的对话列表只列交互式来源的对话。`codex exec` 建的对话来源是 `exec`，被过滤掉。用 `codex app-server` 建的对话来源是 `vscode`，桌面版能列出、能搜到。
- 桌面版打开过一个对话后，会一直占着它的写入权（切到别的对话 6 分钟后仍未放开）。这时外部进程 `thread/resume` 会报 `already has an active writer`。
- `codex queue --thread <ID> --message <文字>` 把一条消息排进对话的队列：
  - 桌面版占着这个对话时，自动执行，实时显示。
  - 没人占着时，消息一直等着；打开 `codex://threads/<ID>`，桌面版加载这个对话，约 3 秒后开始执行。
  - 只建好、没跑过任何一轮的空对话也可以这样交给桌面版。
- 外部进程用 `thread/turns/list` 能读到桌面版正在占着的对话的每一轮（不需要写入权）。

## 目标

1. 派出的 Codex 任务在桌面版里实时可见。
2. 默认接着同一仓库、同一角色上次用的对话做；需要时可以新开，或指定接着某个对话。

## 做法

### 1. 两种执行方式

**交给桌面版（默认）**

1. 按第 2 节确定对话。新开时，用 app-server 建一个空对话并命名（`thread/start`，`approvalPolicy: "never"`，沙箱按设置；`thread/name/set`），不跑任何一轮，然后关掉这个 app-server。
2. 用 `codex queue --thread <ID> --message <任务指令>` 把任务排进对话。指令内容和现在发给 Codex 的一样。
3. 桌面版已经占着这个对话就不用再做什么；否则打开 `codex://threads/<ID>`（会把桌面版切到前台；桌面版没开时由系统启动它）。是否占着，用一次 `thread/resume` 试探：成功说明没人占着，立刻关掉；报 `active writer` 说明有人占着。
4. 跟进度：定时（约 1 秒）用一个只读的 app-server 读这个对话（`thread/turns/list`、`thread/items/list`），找到这次排进去的消息对应的那一轮，把新出现的条目转换成统一事件，写进度、`.log`、汇报。这一轮结束：`completed` 退出码 0；`failed` 为 1；`interrupted` 记 `interrupted`，`signal` 为 `stopped-in-codex`。
5. 打开链接后 60 秒还没开始执行：任务失败，写下面「文案」里那条出错提示。消息仍留在队列里，下次在桌面版打开这个对话时会执行，提示里要说清楚这一点。
6. 本次指定的 model / effort / tier / sandbox 在这种方式下不生效（桌面版执行排队消息时用对话自己的设置）；有指定时，在进度里写一行说明。新开对话时 sandbox 仍按设置写进对话。

**后台执行**

以下两种情况用后台执行：加了 `--background`（派活方在用户说"在后台跑"这类话时加）；或者本机没有装 Codex 桌面版（`codex://` 没有关联的程序）。

- 启动 `codex app-server`（stdio），`initialize` → `thread/start` 或 `thread/resume` → `turn/start` → 等 `turn/completed` → 关闭。本次的 model / effort / tier / sandbox 只作用于这一轮；为 null 时不传，和现在一样。
- 仍收到要用户批准的请求时，一律拒绝，并记一条 `error` 事件，不能卡住。
- `resume` 报 `active writer`（对话在桌面版里开着）：改为交给桌面版，并在进度里说明。
- 对话会出现在桌面版列表里，但不实时显示。进展在 DispatchDock 里看。

**两种方式共同的要求**

- 非 git 目录：保持现在的报错和中文提示。
- 汇报：这一轮最后一条 agent 消息。
- 统一事件和进度：同类动作产生和现在相同的 `kind` 与字段，`progress.log` 原有格式不变。
- `.log` 兼容（协议第 6 节）：现有的查看器读 `.log` 里的 exec 格式。两种方式都把条目转换成和现在 `codex exec --json` 相同格式的行写进 `.log`（包括带 `thread_id` 的 `thread.started`），每行照旧补 `_at`。

### 2. 对话复用

- **默认**：在 `runs.jsonl` 里找同一仓库（规范化路径）、同一角色（都没有角色也算同一类）最近一次用过的对话，接着它做；找不到就新开。
- `--new-thread`（不带值）：这次新开。
- `--thread <对话 ID>`：接着指定的对话，可以是在桌面版里开的。对话不存在就报错退出，不悄悄新开。
- `--new-thread` 和 `--thread` 同时给：参数错误。
- 默认复用的对话已经不存在或被归档：新开，并在进度里说明。
- 同一个对话里的任务按顺序执行：交给桌面版时，由 Codex 的队列排队；后台执行时，等前一个任务结束再开始（用独占锁文件，同时派发也不会撞上）。等待期间任务在列表里显示为进行中。
- 新开的对话命名为 `派发：<仓库目录名>（<角色名>）`，没有角色时为 `派发：<仓库目录名>`。接着旧对话时不改名。

### 3. 停止

- 后台执行：和现在一样，结束派发脚本的进程树。
- 交给桌面版：【实现时核实】从外部对桌面版占着的对话发 `turn/interrupt` 能不能停下这一轮。能停：停止按钮和 `--stop` 照常使用，记 `interrupted`（`stopped-in-app` / `stopped-by-command` 照旧）。不能停：
  - `--stop` 打印下面「文案」里的提示，退出码 1，任务继续。
  - 监控软件里，这类任务不显示「停止」，换成「在 Codex 中打开」。

### 4. 文案（定稿）

进度紧跟在首行和可能的「配置：」行之后。非托管时，同样的行也在「进度：」那行之后打印到标准输出。

| 情况 | 文案 |
|---|---|
| 新开 | `对话：新开 <ID>` |
| 接着上次 | `对话：接着上次的对话 <ID>` |
| 接着指定 | `对话：接着指定的对话 <ID>` |
| 上次的对话没了 | `对话：上次的对话 <旧 ID> 已不存在，已新开 <新 ID>` |
| 指定的对话不存在 | `出错：找不到指定的对话 <ID>` |
| 交给桌面版 | `执行：交给 Codex 桌面版，进展在桌面版里实时显示` |
| 后台执行 | `执行：在后台运行，桌面版里不实时显示` |
| 后台改为交给桌面版 | `执行：这个对话在 Codex 桌面版里开着，改为交给桌面版` |
| 排队等待 | `执行：已排进对话队列，等前面的任务结束` |
| 参数不生效 | `执行：交给桌面版时，本次指定的模型、强度、档位、沙箱不生效` |
| 60 秒没开始 | `出错：Codex 桌面版 60 秒内没有开始执行。任务还在这个对话的队列里，下次在桌面版打开它时会执行` |
| 不能从外部停止时的 `--stop` | `停止：<记录名> 在 Codex 桌面版里执行，请在桌面版里停止` |

监控软件（文案由设计负责人写进 `app/src/shared/copy.ts`）：

- 更多菜单加一项「在 Codex 中打开对话」，打开 `codex://threads/<ID>`。没有对话 ID 的旧任务不显示这一项。ID 必须是 UUID 格式才打开。
- 参数页加两行：
  - 「Codex 对话」：`<ID>（新开）` / `<ID>（接着上次的对话）` / `<ID>（指定的对话）`
  - 「执行位置」：`Codex 桌面版` / `后台`
- 在桌面版里被停止的任务（`stopped-in-codex`）：标题 `在 Codex 桌面版里停止了这个任务`，简称 `Codex 中停止`，说明文字沿用现有的 `stoppedHelp`。

### 5. 协议新增（确认后由设计负责人写进 `docs/protocol.md`，都是 v1 内的可选内容）

- `runs.jsonl` 新事件 `thread`：`{ event: "thread", id, threadId, mode: "new" | "resume" | "specified", runner: "desktop" | "background", at }`。执行方式中途改变时（后台改为交给桌面版）再写一条。
- `interrupted.signal` 新值 `stopped-in-codex`。
- `progress.log` 新前缀 `对话：`、`执行：`。
- `<home>/threads/<threadId>.lock`（只在后台执行时用）：`{ id, pid, at }`，独占创建；持有进程已经不在就视为失效。
- 托管请求的 `args` 新增可选 `thread`（字符串或 null）、`newThread`（布尔）、`background`（布尔）。
- 第 3 节 `.log` 的说明补一句：Codex 适配器写入的是转换成 exec 格式的事件行。

### 6. 发版

版本号 0.1.10 → 0.1.11，打出 Windows 安装包。用户装好后，在「连接」页更新技能。SKILL.md 由设计负责人在验收后更新：写清楚复用规则，以及什么时候加 `--new-thread`、`--thread`、`--background`，让派活方能照用户的口头说法选参数。

## 不做什么

- 不做"刷新桌面版"按钮：交给桌面版执行后，桌面版本身就是实时的。
- 不删除、不改写 Codex 队列里的消息，不直接读写 Codex 的数据库文件，只用 `codex queue` 和 app-server 协议。
- 不改其他干活方；不加改默认行为的配置项；不清理旧对话。
- 不改 SKILL.md 和 `copy.ts`：由设计负责人改，工程只在汇报里写需要同步的地方。

## 允许改动的文件

`skills/codex-dispatch/` 下的脚本、适配器和 `adapters/README.md`；`app/src/`（`shared/copy.ts` 除外）；`tests/`；`tools/verify-real-codex.mjs`；`package.json`、`package-lock.json` 的版本号。

## 验收

- `npm run verify` 通过。
- 假 Codex 测试（假 app-server 和假 `codex queue`）覆盖：
  - 新开、默认复用、`--new-thread`、`--thread`（存在和不存在）、上次的对话没了改新开。
  - 交给桌面版（已占着：不打开链接；没占着：打开链接；60 秒没开始）。
  - 后台执行、后台遇到 `active writer` 改为交给桌面版、同一对话排队。
  - 桌面版里完成、失败、被停止三种结局。
  - 审批请求被拒绝、非 git 目录提示、托管请求带新参数。
  - 测试里打开链接要换成假的，不能真的启动桌面版。
- 事件对照：用一段真实输出（匿名化）做样例，统一事件和进度与同类动作在 exec 下一致；`.log` 里转换后的行交给现有的 exec 映射，得到同一份统一事件。
- 【实现时核实】用真实 Codex 和桌面版，在临时 git 仓库里跑（会把桌面版切到前台几次，汇报里写明）：
  1. 第一次派发：新开对话、打开链接、桌面版执行；DispatchDock 的进度、汇报、退出码完整。
  2. 同一仓库再派一次：同一个对话 ID，桌面版占着，不再打开链接，自动执行。
  3. `--new-thread`：新的对话 ID。
  4. `--background`：后台执行；对话在桌面版里开着时自动改为交给桌面版。
  5. 连续派两个到同一对话：依次执行，两条记录各自对应自己那一轮。
  6. 从外部 `turn/interrupt` 能否停下桌面版里的这一轮。
  7. 桌面版执行排队消息时用的是对话自己的审批和沙箱设置，还是桌面版当前的设置；会不会弹出审批。
  8. 桌面版没开时打开链接，能否启动它并执行。
  - 测试对话不要归档或删除，汇报里列出 ID，验收时设计负责人在桌面版里看。
- 截图：`npm run shots` 产出任务详情的参数页（带两行新参数），以及一个交给桌面版的进行中任务（没有「停止」，有「在 Codex 中打开」；如果第 6 条结论是能停，就照常显示「停止」）。
